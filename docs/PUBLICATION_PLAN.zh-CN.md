# GitHub 保存与开源清单

## 应保存到 Git

| 内容 | 本次处理 / 后续要求 |
| --- | --- |
| 核心算法与运行时接入 | 新建 `shapeshift/`，明确标记为论文算法的重建实现 |
| 测试与 CI | 覆盖选批、aging、兼容性、取消、完成和批处理状态 |
| 安装与依赖 | `pyproject.toml`，dlmserve 固定到完整 commit SHA |
| 使用和复现说明 | README、REPRODUCIBILITY、贡献指南 |
| 小规模输入样例 | 只提交人工长度样例，不包含用户对话 |
| 实验配置与数据来源 | 新实验必须保存命令、种子、硬件、模型 revision、trace hash |
| 论文结果摘要 | 保留原有 CSV，并记录校验和；不当作新实现结果 |
| 图表与作图代码 | 保留历史版本；标注硬编码数值与复现的区别 |
| 许可证与第三方声明 | 保留原 MIT；外部软件和论文模板单独标明来源 |

## 不应直接提交

模型权重、下载的原始数据集、访问令牌、`.env`、SSH 私钥、个人目录、
终端日志、运行缓存、智能体会话、投稿过程材料、签字版权文件、重复压缩包。
本地论文目录中的 `193_LTP.*` 等会议文件不复制到公开仓库。
已跟踪的 5 个运行日志已从新版本索引移除，本地文件仍保留。

大量结果应通过独立 artifact / Release / 数据归档服务保存：公开前检查
分发条件和内容，发布校验和与下载说明。对话正文不是调度研究必需物；
优先保留脱敏长度、到达时间、完成状态与指标。

## 历史与发布边界

当前分支删除文件不会删除旧提交中的文件。历史中仍有早期研究计划、
迁移记录与运行产物。发布旧仓库全部历史之前需要审查这些对象；如只需
公开 ShapeShift，可从审查后的版本创建不带旧历史的新公开仓库。
不要直接 force-push 改写已有仓库历史。

本次改造不把旧结果伪装成重建代码的性能证明。正式可复现论文 release
仍需要真实模型的质量与 GPU 测量、每个基线的匹配配置、以及原始结果到
图表的映射。重建代码可作为明确标注限制的研究实现发布。
